# bringup-check

[English](README.md)

**SO-101이 안 움직이거나, 떨거나, 서보 하나가 뜨거운데 이유를 모르겠을 때.**
`bringup-check`는 Feetech 서보가 원래 보내 주는 숫자(전압·온도·부하·전류·오류 상태·위치 한계)를 읽어, 가장 가능성 높은 **셋업 원인과 해볼 것**을 사람 말로 알려 줍니다.

기존 도구는 "모터가 대답하는지"까지만 봅니다. 이 도구는 **왜** 이상하게 동작하는지에 답하려고 합니다.

```
[문제] 4번 모터(wrist_flex)부터 끝까지 응답이 없습니다
    무슨 일인지: 응답한 모터: [1, 2, 3] / 응답 없음: [4, 5, 6]. 데이지 체인이 한 지점에서 끊긴 모양입니다.
    해볼 것: 3번 모터(elbow_flex)와 4번 모터(wrist_flex) 사이 케이블과 커넥터를 다시 꽂거나 교체해 보세요.
```

## 왜 만들었나

SO-100/101, Reachy Mini 같은 취미용 로봇의 공개 사고 사례 66건(GitHub 이슈·포럼)을 모아 분류했습니다. **66건 중 37건이 셋업 문제**(전원·배선·조립·캘리브레이션)였고, 코드나 부품 불량이 아니었습니다. 아래 진단은 각각 그 실제 사례를 바탕으로 만들었습니다.

| 진단 | 예시 결과 | 바탕이 된 사례 |
|---|---|---|
| 체인 단선 | "3번과 4번 모터 사이 케이블을 확인하세요" | LeRobot #3131 등 |
| 한 모터만 무응답 | "ID 설정이 빠졌거나 서보 고장" | LeRobot #605, Pollen 포럼 |
| 과전압·저전압 | "모터 6개 모두 과전압: 7.6V (보호 상한 7.0V)" | Reachy Mini #589 |
| 정격과 다른 어댑터 | "7.4V용 서보에 12.1V" (`--servo-rating` 지정 시) | Arduino 포럼 |
| 체인 뒤로 전압 하락 | 헐거운 커넥터·가는 케이블 | 전원·배선 사고 다수 |
| 한 서보만 뜨거움 | "다른 서보와 바꿔 끼워 열이 따라가는지 보세요" | ROBOTIS 포럼 |
| 위치 한계·모드 설정 오류 | "위치 한계가 잘못됐습니다 (2100 ≥ 2100)" | Pollen 포럼 |
| 캘리브레이션 이탈·경계 | "엔코더 경계(0/4095) 근처" | LeRobot #3193, #1026 |
| 쥔 채 힘쓰는 그리퍼 | "멈춘 채 계속 힘을 쓰고 있습니다 (부하 85%)" | LeRobot #2819 |
| (선택) 부하 시 전원 처짐 | "5.0V → 4.1V로 떨어졌습니다" | Arduino 포럼 |

## 설치

```bash
pip install "bringup-check[hardware] @ git+https://github.com/bluvtx09/bringup-check"
```

LeRobot을 이미 쓰고 있다면 서보 SDK(`feetech-servo-sdk`)는 이미 설치돼 있습니다.

## 사용법

```bash
# 로봇 없이, 재현한 사고 시나리오로 모든 진단 보기
bringup-check --demo all

# 내 로봇 (읽기만 함: 아무것도 움직이거나 쓰지 않음)
bringup-check --port /dev/ttyACM0 --servo-rating 7.4 --calib auto

# 선택: 모터에 힘을 넣고 현재 자세를 5초 유지하며 전원 검사
bringup-check --port /dev/ttyACM0 --hold-test 5
```

- `--calib auto`는 LeRobot 캘리브레이션 파일을 찾아, 지금 연결된 팔과 맞는 파일을 골라 씁니다.
- `--ids`는 **데이지 체인 순서대로** 적습니다(기본 `1,2,3,4,5,6`). 단선 위치 추정이 이 순서를 씁니다.
- `--lang en|ko`로 언어를 고릅니다(기본은 시스템 언어).
- `--hold-test`만 모터에 힘을 넣습니다. 목표를 현재 위치로 맞춘 뒤 켜서 튀지 않고, 끝나면 원래 토크 상태로 되돌립니다. 그래도 팔을 받칠 준비를 하세요.
- `[문제]`가 있으면 종료 코드 1을 돌려줍니다.

## 결과를 공유해 주세요

진단 기준값은 공개 사례에서 잡은 **출발점이고, 아직 실물로 검증되지 않았습니다.** 정상이든 아니든 로봇에서 돌려 보셨다면 아래 명령의 출력을 이슈로 올려 주시고, 진단이 실제 원인과 맞았는지 알려 주세요.

```bash
bringup-check --port /dev/ttyACM0 --calib auto --share
```

→ [결과 공유하기](https://github.com/bluvtx09/bringup-check/issues/new?template=diagnosis-report.md)

`--share` 출력에는 모터 측정값과 진단 코드만 들어갑니다. 파일 경로나 포트 이름은 들어가지 않습니다.

## 한계

- Feetech STS/SMS 버스 서보(SO-100/101의 STS3215)만 지원합니다. Dynamixel 등은 아직 지원하지 않습니다.
- PWM 서보(SG90, MG996R 등)는 상태를 보내 주지 않아 진단할 수 없습니다.
- 실물 SO-101에서는 아직 돌려 보지 않았습니다. 테스트는 공식 SDK의 호출 형식을 흉내 낸 가짜 버스와, 실제 사고를 흉내 낸 시나리오로 했습니다.
